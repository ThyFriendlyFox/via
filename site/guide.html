Guide

How to use Via, step by step

Here's the whole path from an idea to the files a board maker needs, in plain English. Your AI agent does most of the typing, and Via's checks tell it what's wrong until the board passes.

1 Where Via runs

Via runs on Ubuntu 24.04. If that's your computer, you can go straight to step 2.

On Windows or a Mac, the way in today is a Claude Code cloud environment. It's a Linux machine in the cloud that you use from your browser, and we've written a setup script that installs Via on it. Nobody has run that script on a real environment yet, so we'd like to hear how it goes. The environment's settings are in the repository. We're also making a Docker image, but it isn't public yet.

2 Installing the tools

One script installs the tools Via uses, including KiCad 10, ngspice, Java 21 and FreeRouting. It adds system packages, so it asks for sudo.

$ git clone https://github.com/ThyFriendlyFox/via.git && cd via
$ sudo ./install.sh

On a cloud environment, the setup script does this step for you.

3 Checking the install

workcenter doctor lists each tool Via needs and whether it found it. When nothing's missing, you're ready.

$ workcenter doctor

4 A first run of the checks

Every board goes through 4 checks, in order.

  • ERC checks the schematic's wiring.
  • DRC checks the board's copper and spacing, and that the board matches the schematic.
  • The simulation runs the circuit and holds its numbers to their limits.
  • The export writes the files a board maker needs.

Our small test board passes all 4, so it shows you what a pass looks like. The last line says GREEN.

$ workcenter gates tests/boards/pass-first-design

A copy of it has 1 track moved too close to a pad, so you can see a failure too. After a failure, workcenter next names the fix.

$ workcenter gates tests/boards/fail-drc-clearance
$ workcenter next tests/boards/fail-drc-clearance

5 Starting your own board

workcenter new makes a folder for your board, and we keep it outside Via's own folder. It starts with a design file from our template and an empty parts list.

$ workcenter new ~/my-board

6 Telling your agent what you want

Next, you describe the board to your AI agent in your own words. A good description says what the board does, how it gets power and what it connects to. We use Claude Code, and another agent can start from AGENTS.md.

The agent writes the design as a Python file, following Via's board-design skill. A skill is a written procedure that comes with Via. There's one for each job, from designing a board to pricing its parts.

7 One step at a time

At any point, workcenter next names the one next step. It says what to do, which command to run, why, and what to read. Your agent runs it, fixes what it finds and asks again, until nothing's left.

$ workcenter next ~/my-board

8 The files you order with

When your board passes all 4 checks, the files a board maker asks for are in build/fab. They're the Gerbers, the drill files, the parts list and a PDF of the schematic.

$ workcenter gates ~/my-board

Board makers like JLCPCB and PCBWay take the Gerbers and the drill files when you order.

Version 0.1.0 is our first release, and we're still early. If a step doesn't work for you, we'd like to hear about it on the feedback page or in our Discord.
