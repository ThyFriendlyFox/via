Via: an electronics workcenter for agents

An electronics workcenter for agents. Open source under MIT.

Via holds the tools, skills and gates an agent needs to take a KiCad 10 project to fabrication outputs. It runs ERC, DRC, simulation and export, in that order. A board is done when the last line says GREEN.

Get the code See a board it made

Install on Ubuntu 24.04

$ git clone https://github.com/ThyFriendlyFox/via.git && cd via && sudo ./install.sh

Via is files and commands: any agent that reads a file and runs a shell can use it. On 2026-11-11 a small model took a low-pass filter from a paragraph to 0 ERC errors, 0 DRC errors, 14 corner runs and 22 gerber files, in 38 tool calls.

The gates

A board is done when the last line says GREEN.

Via runs KiCad's rules, ngspice at every corner and the export, in that order. Each drawing below is a board in the repository that a gate stopped, with the numbers its run printed.

rosetta.kicad_sch

ERC: the schematic's electrical rules

Rosetta's first wired schematic put a stick's click on a net named L3, and the shift register read BTN_L3. The ERC named both labels as joined to nothing, with 2 more faults the label sheet had hidden.

tests/boards/fail-drc-clearance

DRC: the board's design rules

KiCad's rules on the routed board; --fab adds a board house's limits. On this fixture 2 tracks pass 0.05 mm apart where the rule asks for 0.20 mm.

tests/boards/fail-sim-corner/sim/diode_ref.cir

SIM: every deck at every corner

ngspice runs each deck as written, at each temperature the project names, and with each part at both ends of its tolerance. This reference is inside its window as written and leaves it hot and cold.

tests/boards/fail-freq-overlap/sim/frequency-plan.json

The frequency plan

Every switching frequency and its harmonics, against every resonance a deck measured. The deck's one bound, on the rail's average, holds; only the plan sees the third harmonic on the filter's peak.

examples/universal-controller/v0.1/rosetta.kicad_pcb

Routing, headless

FreeRouting routes the board from the design file, with no GUI. Rosetta's 4 layers routed once the RP2040's capacitors moved to its corners and its vias shrank to 0.45 mm.

tests/boards/pass-rc-divider/build/fab/

EXPORT: what the fab gets

Gerbers, drill files, the BOM and the schematic PDF, written only from a board that passed every gate.

$ workcenter next tests/boards/fail-sim-corner
NEXT       The circuit is inside its bound as written and outside it at that corner. Change the circuit: a tighter part, another value, another topology. A bound, a rule or a requirement is never changed to pass: the design changes.
RUN        workcenter gates tests/boards/fail-sim-corner
WHY        SIM failed: diode_ref:vref=0.4215933 at 85 C, R1 +5 % (and 5 more corners) not in [0.5, 0.6] (the fixture's reference window, 0.55 V within 0.05 V)
READ       .claude/skills/simulate/SKILL.md, "Corners"
DONE WHEN  the last line starts with GREEN

workcenter next

The next step

After a red run, workcenter next names the one step that is left: what to change, the command, why, what to read, and when it is done. A person and an agent of any size read the same 5 lines.

  • GREEN exit 0
  • RED exit 1
  • SKIPPED exit 2

The exit code says the same as the last line. A run with an absent engine is never GREEN: it is SKIPPED, by name.

How it works

3 engines, 4 gates, 1 verdict.

design.py a Python file that names parts from the KiCad libraries
workcenter design
KiCad project a schematic and a routed board
workcenter gates
ERC · DRC
SIM · EXPORT 4 gates, in order; the last line is the verdict
GREEN
build/fab/ gerbers, drill files, a BOM, a schematic PDF

The engines, all headless

KiCad 10 kicad-cli runs ERC, DRC and the export
ngspice runs every deck at every corner
FreeRouting routes the board

The command line itself needs only Python's standard library. workcenter doctor reports each engine's status. A gate whose engine is absent is skipped by name, and that run is never GREEN.

Each procedure is a Markdown file, a skill: design a board, run the gates, simulate, route, price the parts, write the verification package. The contract lists what a project gets.

Run it

Open source under MIT. Run it on your machine.

On Ubuntu 24.04, install.sh installs KiCad 10, ngspice, Java 21 and FreeRouting. The fixture boards in the repository are the first projects to run.

$ git clone https://github.com/ThyFriendlyFox/via.git && cd via
$ sudo ./install.sh
$ workcenter doctor
$ workcenter gates tests/boards/pass-rc-divider

Where it stands. Via is early and has no release yet. The gates, the corners, the frequency plan and workcenter next run on the fixture boards in every check of the repository. The cloud setup script and the Docker build have not run yet. Chip design, from RTL to a mask layout, is in progress on a branch. The status page has the rest.
