Example project

A fire alarm communicator, designed end to end with Via

Herald connects a fire alarm control panel to a monitoring station over LTE-M, with Wi-Fi as a backup. Via took it from a written brief to a routed four-layer board, 84.4 × 64 mm with 127 parts on one side, and the files a fabricator needs. Every part on the board below is labelled with the information Via gathered for it.

This view is generated from Herald's design file and routed board. Each label shows what Via recorded for that part: its value, footprint and connections; the manufacturer's description and datasheet; why it was chosen; and every simulation that tests it, with the results across temperature and tolerance. Select any part on the board to see its label.

J2 · Q3 · Q4

A phone line for a panel that expects one

Fire panels report by telephone. Herald supplies the panel's dialer with a current-limited line from its 24 V input and detects when the dialer goes off hook.

U5 · GPIO7

Tone decoding in firmware

A Goertzel filter decodes the dialer's DTMF digits to the limits of ITU-T Q.24, verified on the host with a complete Contact ID call.

GPIO14 · R25–R27

Line tones from a PWM pin

Dial tone, handshake and acknowledgement come from a microcontroller pin through two RC stages. Simulation caught a first design that was too weak for the line before any board was made.

J3 · R31 · R32 · U8

Three supervised inputs

End-of-line resistors let one ADC reading tell a closed contact, an intact loop and a cut wire apart, with at least 0.2 V of margin at every simulated corner.

K1 · Q6 · J7

A fail-safe trouble relay

The relay is held on while Herald is healthy. A power loss or a reset releases it, and the panel reports the fault.

U3 · J4 · J5

Cellular first

A Quectel BG95-M1 LTE-M module with a nano SIM, level-shifted to the ESP32-S3, with a hand-routed 50 Ω antenna feed.

U5

Wi-Fi as backup

The ESP32-S3's own radio, with an external antenna connector for installation in a metal cabinet.

Q5 · R21

When both paths fail

Herald drops the line feed, so the panel reports a communication fault just as it would for a cut phone line.

Design as code

Your board is a Python file you can review

Parts, connections and placement live in one file under version control. Change a line, regenerate, and Via rebuilds the schematic and the routed board, with no manual steps in a GUI.

workcenter design design.py --route writes Herald's KiCad schematic and routed board from its design file, so every change to the board is a change you can review.

Process

From a design file to fabrication files in four steps

  1. 01

    Describe the board in code

    workcenter design design.py --route turns a Python file of KiCad library parts into a schematic and a fully routed board.

  2. 02

    Run the four checks

    workcenter gates <project> runs the electrical rules, the design rules, simulation and export, in that order, and ends with a single verdict.

  3. 03

    See exactly what to fix

    workcenter next <project> names the next step: the command to run, why the last check failed, and the guide to read.

  4. 04

    Send the files to your fabricator

    Gerbers, drill files, a bill of materials and a schematic PDF, written to build/fab/ only for a board that passed every check.

Four checks before any board is released

Each check reports on one line, and the last line is the verdict. The exit code matches it, so scripts and CI can rely on it. If a tool is missing, the run is never reported as a pass.

  • GREEN exit 0
  • RED exit 1
  • SKIPPED exit 2
  1. 01

    ERC

    Electrical rules: KiCad's electrical rule check on the schematic.

  2. 02

    DRC

    Design rules: KiCad's design rule check on the routed board, with your fabricator's limits added by --fab.

  3. 03

    SIM

    Simulation: ngspice runs every circuit simulation and holds each measured value to its limit, as designed and at every corner.

  4. 04

    EXPORT

    Fabrication files: Gerbers, drill files, the bill of materials and the schematic PDF, written to build/fab/.

Simulation

Tested across temperature and part tolerance before you build

A circuit that works on paper can fail when the board is hot or a part sits at the edge of its tolerance. Via simulates those cases automatically, so problems surface before the first prototype is made.

Temperature

Every simulation runs at each temperature the project specifies, and each range records its source.

Tolerance

Each part is tested at both ends of its tolerance and halfway between. Up to 64 combinations run exhaustively; beyond that, Via runs a worst case for each limit plus the project's Monte Carlo draws.

Frequency plan

Switching frequencies and their harmonics are checked against every resonance the simulations measure.

Works with any agent

Engineering judgement built into the checks

Via turns the questions an experienced engineer asks into automated checks, and every failure comes with its next step. The goal is for a small, fast model to reach the same working board as the largest one.

Proven with a small model

A small model took a low-pass filter from a one-paragraph brief to a board with no ERC or DRC errors, 14 simulated corners and 22 Gerber files, in 38 tool calls. Seven of the eight problems it hit now stop with the exact fix.

Reviewed by an engineer

An engineer found a circuit that had passed the checks but failed at 85 °C. Temperature and tolerance corners are now part of every simulation.

Known gaps

One check is still missing: a simulation written by hand is not yet tied to the board's parts. The roadmap tracks it, and the development log records progress.

Open-source engines, all running headless

KiCad 10 kicad-cli runs ERC, DRC and the export
ngspice runs every deck at every corner
FreeRouting routes the board

The command-line tool needs only Python's standard library. workcenter doctor reports the status of each engine, and a check whose engine is missing is reported as skipped, never as passed.

Every procedure is written as a skill an agent can follow: designing a board, running the checks, simulating, routing, pricing parts and writing a verification package. The contract lists everything a project receives.

Get started

Free and open source under the MIT license

On Ubuntu 24.04, install.sh installs KiCad 10, ngspice, Java 21 and FreeRouting. Start with one of the example projects, then describe your own board.

$ git clone https://github.com/ThyFriendlyFox/via.git && cd via
$ sudo ./install.sh
$ workcenter doctor
$ workcenter gates examples/fire-alarm-communicator/v0.1

Current status. Via is in early development and has no release yet. The checks, the simulation corners, the frequency plan and workcenter next run in every test of the repository. The Docker image and the cloud setup script are not released yet, and chip design, from RTL to mask layout, is in progress. The status page has the details.
