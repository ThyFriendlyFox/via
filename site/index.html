An electronics workcenter for agents

Via holds the tools, skills and gates an agent needs to take a KiCad 10 project to fabrication outputs. It runs ERC, DRC, simulation and export, in that order. A board is done when the last line says GREEN.

Example project · examples/fire-alarm-communicator

A fire panel dials. Herald answers.

Herald sits beside a fire alarm panel and reports what the panel reports to a monitoring station: over LTE-M first, over Wi-Fi when the cell path is down. Via took it from a page of notes to a routed 4-layer board, 84.4 x 64 mm, 127 parts, every part on the front. Pick a signal and see where it goes.

Signal 1 of 5

The dialer calls

Enters
J2, the panel dialer's phone line. Herald feeds it 20 to 28 mA from the 24 V input.
Herald reads
Off hook: 0.776 to 1.319 V at every corner. On hook: 0.040 V at most.
The firmware's line
Off hook above 0.4 V on GPIO5, for 20 ms

The board plays dial tone and the handshake from a PWM pin, and the firmware decodes the dialer's 16 DTMF digits with a Goertzel filter, tested on the host. The tone sequencer and the report to the station, over LTE-M through the BG95 or over Wi-Fi, are not written yet.

The drawing is the board: site/showcase/draw_face.py writes it from the design file and the routed board, in the board's own millimetres. The bright paths go from part to part; they are not the tracks. The readings are what workcenter sim measured: sim/loop_offhook.cir, sim/loop_onhook.cir, and sim/zone_short.cir to sim/zone_open.cir for zone 1. The firmware's zone classifier, hook, DTMF decoder and Contact ID are written and tested on the host; the tone sequencer, the modem's commands, the station's protocol, the lights and the relay's watchdog are not written yet.

J2 · Q3 · Q4

A phone line that is not there

A fire panel reports by phone. Herald feeds the dialer's line a current-limited loop from the 24 V input, and R22 reads the loop current to see the dialer go off hook.

U5 · GPIO7

DTMF without a DTMF chip

A Goertzel filter per frequency, 25.6 ms windows at 8 kHz, takes and refuses what ITU-T Q.24 says a receiver must. Host tests play a whole Contact ID call through it.

GPIO14 · R25–R27

Tones from a PWM pin

Dial tone, the handshake and the kissoff go through 2 RC poles onto the line's 600 ohm. The first poles gave 28 mV; the deck found it, and the poles changed.

J3 · R31 · R32 · U8

3 supervised inputs

Each loop ends in a 4.7k resistor, so 1 ADC reading tells a closed contact, a whole loop and a cut wire apart, 0.2 V or more from each threshold at every corner.

K1 · Q6 · J7

A relay that fails safe

K1 is held on while Herald is healthy. A lost supply or a reset opens it, and the panel sees its trouble input change.

U3 · J4 · J5

LTE-M first

A Quectel BG95-M1 with a nano SIM. A TXS0104E carries its 1.8 V UART to the ESP32's 3.3 V. The antenna feed is 50 ohm, drawn by hand.

U5

Wi-Fi second

The ESP32-S3's own radio, on the module's u.FL, for an antenna outside a metal cabinet.

Q5 · R21

When neither path works

The firmware drops the line feed. The panel sees no phone line and reports its own communication trouble, as it does for a cut line.

The path

Design. Gate. Fix. Done.

  1. 01

    Design as code

    workcenter design design.py --route builds a schematic and a routed board from a Python file. The file names parts from the KiCad libraries. No GUI at any step.

  2. 02

    4 gates, in order

    workcenter gates <project> runs ERC, DRC, SIM and EXPORT. It prints 1 line for each gate. The last line is the verdict.

  3. 03

    The next step

    workcenter next <project> names the one step that is left, its command, and the fix for the first failure.

  4. 04

    Fabrication outputs

    Gerbers, drill files, a BOM and a schematic PDF go to build/fab/. They come from a board that passed every gate.

A board is done when the last line says GREEN.

The exit code says the same as the line. A run with an absent engine is never GREEN.

  • GREEN exit 0
  • RED exit 1
  • SKIPPED exit 2
  1. 01

    ERC

    KiCad's electrical rules, on the schematic.

  2. 02

    DRC

    KiCad's design rules, on the routed board. --fab adds a fabrication house's limits.

  3. 03

    SIM

    ngspice runs every deck. Each measured value is held to its bound, as written and at each corner.

  4. 04

    EXPORT

    Gerbers, drill files, the BOM and the schematic PDF, written to build/fab/.

Corners

A bound holds at every corner, or it does not hold.

A circuit that works as written can leave its limits when a part is at the end of its tolerance, or the board is hot. The SIM gate runs those cases before the board is built.

Temperature

Every deck runs at each temperature the project names. The project gives each range with its source.

Tolerance

Each part runs at both ends of its tolerance and half-way to each. Every combination of the ends runs up to 64 runs. Above that, the gate runs a worst case for each bound and the Monte Carlo draws the project names.

Frequency plan

The gate holds every switching frequency and its harmonics against every resonance a deck measured.

Any agent

The knowledge is in the gates, not in the model.

The aim: a small model reaches the same working board as a large one. So each question an engineer asks is a gate that runs, and each next step is a command that names it.

A small model built a board

On 2026-11-11 a small model took a low-pass filter from a paragraph to 0 ERC errors, 0 DRC errors, 14 corner runs and 22 gerber files. It took 38 tool calls and met 8 traps. Each trap but 1 now stops with the line to write.

An engineer reviewed a board

The gates had passed a circuit that fails at 85 C. The engineer found it. That question is now the SIM gate's corners: the fixture above fails at 85 C.

What is still open

1 trap has no gate yet: nothing holds a deck typed by hand to the board's parts. The roadmap names it, and the devlog has each day.

How it works

3 engines, 4 gates, 1 verdict.

design.py a Python file that names parts from the KiCad libraries
workcenter design
KiCad project a schematic and a routed board
workcenter gates
ERC · DRC
SIM · EXPORT 4 gates, in order; the last line is the verdict
GREEN
build/fab/ gerbers, drill files, a BOM, a schematic PDF

The engines, all headless

KiCad 10 kicad-cli runs ERC, DRC and the export
ngspice runs every deck at every corner
FreeRouting routes the board

The command line itself needs only Python's standard library. workcenter doctor reports each engine's status. A gate whose engine is absent is skipped by name, and that run is never GREEN.

Each procedure is a Markdown file, a skill: design a board, run the gates, simulate, route, price the parts, write the verification package. The contract lists what a project gets.

Run it

Open source under MIT. Run it on your machine.

On Ubuntu 24.04, install.sh installs KiCad 10, ngspice, Java 21 and FreeRouting. The fixture boards in the repository are the first projects to run.

$ git clone https://github.com/ThyFriendlyFox/via.git && cd via
$ sudo ./install.sh
$ workcenter doctor
$ workcenter gates tests/boards/pass-rc-divider

Where it stands. Via is early and has no release yet. The gates, the corners, the frequency plan and workcenter next run on the fixture boards in every check of the repository. The cloud setup script and the Docker build have not run yet. Chip design, from RTL to a mask layout, is in progress on a branch. The status page has the rest.
