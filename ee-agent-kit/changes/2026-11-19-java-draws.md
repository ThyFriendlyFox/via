### Fixed
- Via no longer runs FreeRouting on a Java that cannot draw its window. install.sh installs `openjdk-21-jre` when the JVM it records (`java-21-openjdk-<arch>`) has no `lib/libawt_xawt.so`; another JDK's library under `/usr/lib/jvm` no longer counts. The java step records a JVM that has it, and with `REQUIRE_FREEROUTING=1` it stops when none has. When the recorded java cannot draw and the first java on PATH is a Java 21 that can, Via runs that one and says why. When no java can, `design --route` skips the route with the java, where it came from and the missing library, and doctor's java row says the same. A failed route names the java that ran and the exception it threw. In CI run 44515796762 the recorded JVM was Ubuntu's headless runtime, and 13 routing tests ended in `FreeRouting exited 1`.
- The router and doctor's java row now hold every java to the same check: the java is there, its JVM has `lib/libawt_xawt.so`, and it is Java 21 or newer. That holds for the java set by `JAVA`, the recorded one and the first on PATH. `workcenter autoroute` skips with the java and why instead of running a java the router refuses. A record that cannot be read or holds more than 1 line is named, and doctor no longer stops on a java that names no version.
