### Changed
- The full health gate runs on GitHub. `main` takes no commit that its gate did not pass on that exact commit: `make verify` for a `full` change, `make verify-site` for a `fast` one; on GitHub, the `verdict` check. A pull request merges only when `verdict` is green on its head and the branch holds `main`'s tip, by `gh pr merge --match-head-commit`. A release is tagged only after a `full` run on its commit. A push to a work branch needs only `make check`, new: `make lint`, `make kit` (new: the gate's kit checks alone) and the kit's own tests, with no engine and no lock. A branch with no pull request is gated by `gh workflow run ci.yml --ref <branch>`, always `full`. AGENTS.md, README.md, the pull request template, CONTRIBUTING.md, PROCESSES.md P14, P31, P33 and P35, RELEASING.md, WEEKLY.md, VERIFICATION.md, the `land` and `lead` skills and the lead's kit say the same, and `tests/test_gate_rule.py` holds them to it. `ee-agent-kit/lead/gate-and-push.sh` stays for a machine with no CI.
