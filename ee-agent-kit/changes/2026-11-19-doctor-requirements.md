### Changed
- `workcenter doctor` holds the venv to `requirements.txt`: a new `requirements` row names a pinned package that is missing or at another version, and the 1 command that puts it right (install.sh's `pip install -q -r requirements.txt`); either makes Via `degraded`. Packages that no line of requirements.txt or its dependencies accounts for are a note, never a fault. The row reads installed metadata and runs no pip. A package whose metadata cannot be read (an old package's METADATA that is not UTF-8, say) is said under `not read`; if requirements.txt pins it, it is a fault of that pin, which degrades. Any error in the check is an advisory `not checked:` line, never a crash of doctor, and the status line then reads `ok, requirements not checked` (`--json`: `not_checked`). The image build refuses an image whose venv disagrees with the requirements.txt in its tag (a pin missing, at another version, or whose package cannot be read), and an image whose row could not be checked. Before, the `venv` row read `ok` whenever the folder was there: on 2026-11-18 a stray install.sh run added 12 packages and the line did not change.
