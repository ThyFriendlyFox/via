### Added
- `workcenter autoroute --apply <project>` routes a hand-drawn KiCad board headless: the board file is read into kicadgen's DSN writer, FreeRouting routes it, the copper is written back into the `.kicad_pcb`, and the DRC judges it. While the project ignores unconnected items, KiCad's DRC checks no connection and FreeRouting 1.9.0 logs no count, so the run says `open connections not judged` and is SKIP (exit 2), never a pass. A paste or mask window with no copper layer is skipped; a wrong `.kicad_pro` is refused by its name and place, not a traceback; an outline the first cut refuses names what is drawn. New fixture `tests/boards/route-me` (ROADMAP item 15, "Headless autoroute for hand-drawn boards").
- `autoroute --apply` refuses to write the person's board, and leaves it as it was, when it is read-only, open in KiCad (`~<board>.lck` beside it) or changed while the router ran; the first 2 are checked before the route too. A board that is a symbolic link is written through to its target, with its mode kept; a write that fails is an ERROR line, not a traceback. The route only adds copper: the person's tracks and vias stay as written, a locked one with its lock and uuid, and a route that adds nothing leaves the file byte for byte. A second run keeps the first run's copy of the board (`build/route/<name>.before.kicad_pcb`, then `.before-2`, ...).
